## 2. ใบลดหนี้ `CN-{yy}-NNNN` + คืนเงิน + รายงานใบลดหนี้ (ทำก่อน — รายงานภาษีขายต้องใช้)

### 2.1 อ้างบิลได้สองแบบ (Q2)

| | อ้างใบกำกับ `IV-` | อ้างใบเสร็จ `RC-` (จ๊อบที่ไม่ได้ออกใบกำกับ) |
|---|---|---|
| เมื่อไหร่ | จ๊อบมีใบกำกับแล้ว — **ต้องอ้าง `IV-` เท่านั้น** อ้าง `RC-` ของจ๊อบนั้นไม่ได้ (`CREDIT_NOTE_USE_TAX_INVOICE`) กันลดซ้ำสองทาง | จ๊อบมีใบเสร็จแต่ไม่มีใบกำกับ |
| บรรทัดให้เลือก | `TaxInvoiceLine` (สำเนาในใบกำกับ) | บรรทัดที่ลูกค้าอนุมัติของทุกใบเสนอราคาที่ใช้อยู่ (`QuotationLine` — ล็อกแก้ไม่ได้แล้วหลังออกใบเสร็จตามกฎข้อ 21 จึงคงที่) · สำเนาลงใบลดหนี้ตอนออก |
| ชื่อเอกสารที่พิมพ์ | "ใบลดหนี้ / ใบกำกับภาษี" — มีช่องตามมาตรา 86/10 ครบ | "ใบลดหนี้" + ข้อความ "อ้างอิงใบเสร็จรับเงิน ไม่ใช่เอกสารทางภาษี" |
| VAT | อัตราของใบกำกับ | `Job.VatIncluded` ของจ๊อบ (ไม่คิด VAT → VAT 0) |
| รายงานภาษีขาย | ส่วนที่ 1 (ยอดติดลบ) | ส่วนที่ 2 คู่กับใบเสร็จที่ยังไม่ออกใบกำกับ (Q1) |

- ใช้เลข `CN-` ชุดเดียวกันทั้งสองแบบ (ต่อสาขา/ปี) · ผูก `JobId` เสมอ
- Q9 (ยืนยันแล้ว): ถ้าจ๊อบมีใบลดหนี้อ้าง `RC-` แล้ว ออกใบกำกับไม่ได้ (`TAX_INVOICE_RECEIPT_CREDITED`)

### 2.2 กฎ (บังคับที่ API)
- ผู้ออก = **Manager เท่านั้น** (`CREDIT_NOTE_FORBIDDEN`) · ฟีเจอร์แพ็กเกจ `TaxInvoice` (ล็อกเหมือนใบกำกับ)
- **ต้องเลือกอย่างน้อย 1 บรรทัดของบิลที่อ้าง** (`CREDIT_NOTE_LINES_REQUIRED`) ห้ามบรรทัดนอกบิล · บิลต้องเป็นของสาขาเดียวกัน (`CREDIT_NOTE_SOURCE_NOT_FOUND`)
- ต่อบรรทัด: ลดเป็น **จำนวน** (≤ จำนวนเดิม − ที่ลดไปแล้ว) หรือ **ยอดเงิน** (≤ ยอดสุทธิคงเหลือของบรรทัด) (`CREDIT_NOTE_EXCEEDS_LINE`) · บิลหนึ่งใบมีใบลดหนี้ได้หลายใบจนยอดคงเหลือเป็น 0
- เหตุผลบังคับ เลือก 1 ใน 5 (กรณีตามมาตรา 82/10): ลดราคาเพราะสินค้า/บริการไม่ตรงหรือชำรุด · คืนสินค้า · บริการผิดข้อกำหนด · คำนวณราคาผิดสูงกว่าจริง · อื่นๆ (ต้องระบุ) (`CREDIT_NOTE_REASON_REQUIRED`)
- สำเนาผู้ขาย (ชื่อ/ที่อยู่/เลขผู้เสียภาษี/**สนญ.-สาขา จาก Q6**) และผู้ซื้อ · **มูลค่าตามบิลเดิม · มูลค่าที่ถูกต้อง · ผลต่าง · VAT ของผลต่าง** · ปัดเศษสูตรเดียวกับใบกำกับ
- `RequestId` กันกดซ้ำ · `ActivityEvent credit_note.issued` · **ยกเลิก/แก้ไม่ได้ (Q8)**

### 2.3 คืนเงิน (Q3)
- Entity `CreditNoteRefund`: ช่องทาง (cash/transfer/card/qr — ชุดเดียวกับ `PaymentMethod`) · ยอด · อ้างอิง · ผู้คืน/เวลา · `RequestId`
- บันทึกพร้อมตอนออกใบลดหนี้ (ค่าเริ่มต้น = ยอดรวมใบลดหนี้) หรือบันทึกทีหลังได้ · คืนได้หลายครั้ง **รวมไม่เกินยอดใบลดหนี้** (`CREDIT_NOTE_REFUND_EXCEEDS`) · ยอด 0 ได้ (เช่น หักกลบกับงานถัดไป — ต้องใส่หมายเหตุ)
- ผู้บันทึก = Manager · ลบรายการคืนเงินไม่ได้ (เป็นหลักฐานเงินออก) · สถานะใบลดหนี้: ยังไม่คืน / คืนบางส่วน / คืนครบ (สี+ไอคอน+ข้อความ)
- **ไม่เปลี่ยน `Payment`/`Receipt` เดิม** และไม่แตะสต็อก · ยอดขายในรายงานเดิม (ยอดขาย-ต้นทุน-กำไร · แดชบอร์ด) **ยังไม่หักใบลดหนี้** ในรอบนี้ — ระบุข้อจำกัดบนหน้ารายงาน

## 4. รายงานภาษีซื้อ `/reports/input-vat` (ต้องเก็บข้อมูลใหม่ก่อน)

### 4.1 บันทึกใบกำกับภาษีซื้อ
- Entity ใหม่ `PurchaseTaxInvoice` (shard/branch · SupplierId? · สำเนาชื่อ/เลขผู้เสียภาษี/สาขาผู้ขาย · เลขที่ใบกำกับ · วันที่ใบกำกับ · มูลค่า · VAT · เดือนที่ใช้สิทธิ์ (Q5) · GoodsReceiptId?/PurchaseOrderId? · หมายเหตุ · ไฟล์สแกน (Attachment kind ใหม่) · ผู้บันทึก · VoidedAt/Reason)
- กันซ้ำ: เลขผู้เสียภาษีผู้ขาย + เลขที่ใบกำกับ ซ้ำในสาขาไม่ได้ (`PURCHASE_TAX_INVOICE_DUPLICATE`) · ยกเลิกได้พร้อมเหตุผล (ไม่ลบ)
- `svc_Supplier` เพิ่ม `BranchNo` (nullable) — migration
- ทางเข้า: หน้า PO/GRN ปุ่ม "บันทึกใบกำกับภาษีซื้อ" (เติมยอดจาก GRN × ต้นทุน × VAT ของ PO ให้แก้ได้) · หน้า "ภาษีซื้อ" บันทึกเองไม่ผูก PO (Q4)
- สิทธิ์ Manager/Office (ฟีเจอร์ `Purchasing`)

### 4.2 รายงาน
- เลือกเดือนภาษี (ตามเดือนที่ใช้สิทธิ์) · คอลัมน์: ลำดับ · วันที่ใบกำกับ · เลขที่ · ชื่อผู้ขาย · เลขผู้เสียภาษี · สนญ./สาขา · มูลค่า · ภาษี · อ้างอิง GRN/PO · ยอดรวม · Excel + พิมพ์
- ตัวช่วยตรวจ: GRN ของ PO ที่มี VAT ในเดือนนั้นที่ยังไม่บันทึกใบกำกับ (แยกรายการเตือน ไม่ใช่ส่วนของรายงาน)

## 6. ความเสี่ยง
- **[RISK]** รายงานภาษีเป็นเอกสารยื่นสรรพากร — แผนนี้ไม่ใช่คำแนะนำทางภาษี ต้องให้ฝ่ายบัญชีตรวจรูปแบบรายงานก่อนใช้จริง

- ใบเสร็จ `RC-`/`SL-` ที่มี VAT แต่ไม่มีใบกำกับ อาจทำให้ภาษีขายในรายงานต่ำกว่ายอดที่ต้องเสียจริง (Q1)

## 8. สิ่งที่ทำจริง (หัวข้อ 3–4 · 2026-11-09 · เว็บ v1.20.1)

API ดู docs/03 §19
- Backend: `Domain/Entities/PurchaseTaxInvoice.cs` · `Application/Pos/TaxReportService.cs` · `Infrastructure/Persistence/TaxReportRepository.cs` ·
  `TaxReportsController` · migration `AddPurchaseTaxInvoice` (ตารางใหม่ 1 ตาราง — ไม่แก้ตารางเดิม) · ลบอู่ self-serve ลบตารางนี้ด้วย
- **ภาษีขาย**: ส่วนที่ 1 = IV- + ใบลดหนี้ที่อ้าง IV- (ติดลบ) · ส่วนที่ 2 = RC- ของจ๊อบที่ไม่มี IV- · SL- ที่ชำระแล้วไม่ยกเลิก · ใบลดหนี้ที่อ้าง RC-
  · `[BIZ]` RC- ของจ๊อบที่ออก IV- ทีหลัง (แม้คนละเดือน) ไม่อยู่ในส่วนที่ 2 ของเดือนไหนเลย กันนับซ้ำ — รายงานเดือนเก่าที่เปิดดูหลังออก IV- จะเปลี่ยน
  · SL- ที่ยกเลิกทีหลังหายจากเดือนเดิม (ไม่มีรายการติดลบในเดือนที่ยกเลิก)
- **ภาษีซื้อ**: หน้าเดียว `/reports/input-vat` ทั้งบันทึก ยกเลิก และรายงาน · ตัวช่วยเตือนใบรับสินค้าของ PO ที่มี VAT ที่ยังไม่บันทึก (ย้อนหลัง 6 เดือน) กดบันทึกจากแถวนั้นได้
- **ต่างจากแผน**: ไม่เพิ่ม `svc_Supplier.BranchNo` — เก็บสาขาผู้ขายในใบกำกับแต่ละใบแทน (ไม่ต้องแก้ฟอร์มซัพพลายเออร์) · ไม่มีแนบไฟล์สแกน ·
  ไม่มีปุ่มบนหน้า PO/GRN (บันทึกจากหน้าภาษีซื้อ) · ยังไม่มีพิมพ์ A4 (ส่งออก Excel ได้ครบพร้อมหัวรายงาน) · เมนู Reports มีหัวข้อใหม่ "ภาษี" (ย้ายใบลดหนี้มาอยู่ที่นี่)
- ผลตรวจ: `dotnet test` **1726 ผ่าน / 24 ข้าม** (เพิ่ม `TaxReportServiceTests.cs` 17) · เว็บ `tsc -b`/`vite build` ผ่าน · เบราว์เซอร์ด้วย API จำลอง:
  หน้าภาษีขาย 2 ส่วน + ใบลดหนี้ติดลบ + Excel 2 แผ่น (อ่านไฟล์กลับมาตรวจแล้ว) · ภาษีซื้อ: เติมจากใบรับสินค้า → บันทึก (payload ถูก · เดือนที่เลือกได้ 7 เดือน) ·
  เหตุผลปุ่มปิด · ปุ่ม "ใช้ 7%" · ยกเลิกพร้อมเหตุผล
- **ยังไม่ได้ทดสอบกับ API/ฐานจริง** — query ใหม่ (join Receipt–Job + `NOT EXISTS` TaxInvoice · ยอดใบรับสินค้าแบบ subquery `SUM` · unique index แบบมีเงื่อนไข) ยังไม่เคยรันบน SQL Server
- **[RISK]** รูปแบบรายงานยังไม่ผ่านฝ่ายบัญชี · หัวรายงานต้องมีเลขผู้เสียภาษีในข้อมูลสาขาเดิม (ไม่มี = ขึ้นเตือนบนหน้า)
