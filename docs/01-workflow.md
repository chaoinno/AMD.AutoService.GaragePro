| waitparts | inprogress | รับของเข้าคลัง (GRN) + เบิกให้งานนั้น · ของชำรุดไม่นับเป็นของใช้ได้ | คลัง · เว็บ |
| inprogress | qc | ทุกรายการที่อนุมัติเสร็จ + มีรูปก่อน–หลังครบ | ช่าง · มือถือ |
| qc | inprogress | QC ตีกลับ ต้องระบุปัญหา + ความสำคัญ (สูง/ปานกลาง/ต่ำ) · เพิ่มงานแก้ไขให้ช่าง | หัวหน้ากะ · มือถือ |

## 3. Sub-flows รายโมดูล

### 3.1 รับรถ (Intake) — 6 ขั้น · Flutter · **[UI]**
1. ค้นหาลูกค้าและรถ (เลขงาน/ทะเบียน/ชื่อ/เบอร์)
2. ยืนยันรถและการนัดหมาย
3. บันทึกสภาพรถขณะรับ — อาการที่แจ้ง, ไฟเตือน, ระดับน้ำมัน (8 ระดับ E→F), เอกสารในรถ, อุปกรณ์เสริม, เลขไมล์
4. ถ่ายรูปรอบคัน 5 มุมบังคับ — front / rear / left / right / dash(เลขไมล์)
5. ตรวจทานก่อนเปิดงาน
6. เปิดงานสำเร็จ + QR ติดรถ

- **[UI]** แถบล่างตรึง (sticky action bar) + บันทึกร่างทุกขั้น · ออกจากฟอร์มต้องยืนยัน
- **[ASSUME]** ไม่พบลูกค้าในข้อมูลหลัก → สร้างข้อมูลชั่วคราว + ส่งคำขอเชื่อมข้อมูล `REQ-xxxx` (ดู Open Question #1)
- **[UI]** ออฟไลน์ → ใช้รหัสชั่วคราว `TMP-` + ป้าย "รอซิงก์" **ห้ามแสดงเป็นเลขงานจริง**

### 3.2 ตรวจเช็คสภาพรถ (Inspection) — 8 หมวด 31 รายการ · Flutter · **[UI]**

| engine · เครื่องยนต์และของเหลว | 5 | น้ำมันเครื่อง, น้ำหล่อเย็น, น้ำมันเบรก/คลัตช์, สายพาน, รอยรั่วซึม |
| brake · เบรก | 5 | ผ้าเบรกหน้า*, ผ้าเบรกหลัง, จาน/ดรัม*, ท่อและสายเบรก, เบรกมือ |
| susp · ช่วงล่าง | 4 | โช้คหน้า, โช้คหลัง, ลูกหมาก/ปีกนก, บูชเหล็กกันโคลง |

`*` = ผูกกับอาการที่ลูกค้าแจ้ง (cust) · `†` = ไม่บังคับ (optional)

- 4 ผลลัพธ์: `ok` ปกติ / `watch` ควรเฝ้าระวัง / `fix` ต้องซ่อม / `na` ไม่เกี่ยวข้อง
- **[BIZ]** `na` **ต้องมีเหตุผล** (4 ตัวเลือก: อุปกรณ์ไม่มีในรุ่นนี้ / ลูกค้าไม่อนุญาตให้ถอด / ต้องยกรถ / รถไม่ติดเครื่อง)
- `fix`/`watch` → แผ่นรายละเอียด: severity (เล็กน้อย/ปานกลาง/รุนแรง), note, photos, video, งานที่แนะนำ, urgency (ทำครั้งนี้/ภายใน 1 เดือน/ภายใน 6 เดือน)
- ผลตรวจ **ถูกล็อก** เมื่อส่งแล้ว (เว็บอ่านได้ แก้ไม่ได้)

### 3.3 ใบเสนอราคา (Quotation) — Web · **[UI]** 3 พาเนล
- ดึงผลตรวจ (`FINDINGS`) มาเป็นบรรทัด แยก 2 กลุ่ม: **ลูกค้าขอ** (cust) vs **ช่างแนะนำ** (tech)
- Catalog: part + labor · แสดง `stock / reserved / onorder / eta / cost / price` · ต้นทุนเห็นตามสิทธิ์
- Line editor: จำนวน / ราคา / ส่วนลด / โปรโมชัน / ช่างผู้รับผิดชอบ / หมายเหตุ
- โปรโมชัน: ไม่มี / ลูกค้าประจำ −5% / โปรเบรกครบชุด −300 / ประกันคู่สัญญา −10%
- **เตือน**: ของไม่พอ, รายการซ้ำ, กำไรขั้นต้นติดลบ/ต่ำ, มีคนแก้พร้อมกัน (ขอสิทธิ์แก้คนเดียว)
- Quotation status: `draft` → `sent` → `partial`/`approved`/`rejected` · `superseded` · `expired`

### 3.4 ลูกค้าอนุมัติ (Approval) — Flutter · **[BIZ]**
- อนุมัติ/ไม่อนุมัติ **รายบรรทัด** · ไม่อนุมัติต้องเลือกเหตุผล (5 ตัวเลือก: ยังไม่พร้อมจ่ายรอบนี้ / ขอทำครั้งหน้า / ขอปรึกษาที่บ้านก่อน / ราคาสูงกว่าที่คาด / จะไปทำที่อื่น)
- สรุปยอดอัปเดตสด → ตรวจทาน → ข้อความยินยอม → ลายเซ็นเต็มจอ
- **[BIZ]** เก็บ: ลายเซ็น + เวลา + อุปกรณ์ + พนักงานผู้รับรอง + **quotation version**

### 3.5 ซ่อม (Repair) — Flutter
- Task status: `todo` / `doing` / `done` / `blocked`(รออะไหล่) / `pending`(รอลูกค้าอนุมัติ) / `fix`(แก้ไขจาก QC)
- จับเวลา start/pause/resume ต่อ task
- **[BIZ]** รูปก่อน–หลัง **บังคับต่อรายการ** ก่อนปิด · เก็บเวลา + ชื่อผู้ถ่ายทุกรูป
- แจ้งรออะไหล่: ของ + จำนวน + เหตุผล (4: ของหมดสต็อกสาขา/สั่งผิดรุ่น/ของที่ได้มาชำรุด/ต้องสั่งจากศูนย์) + ETA (3: ได้พรุ่งนี้/ภายใน 3 วัน/ยังไม่ทราบ)
- **[BIZ]** แจ้งงานเพิ่มเติม → **ยังไม่ถือว่าอนุมัติ** ล็อกเฉพาะรายการนั้นจนลูกค้าอนุมัติเวอร์ชันใหม่

### 3.6 QC — Flutter · เช็กลิสต์ 6 ข้อ
เบรกปกติไม่มีเสียง / ของเหลวครบไม่รั่ว / ช่วงล่างแน่นไม่เคาะ / ลมยาง+น็อตล้อครบ / แอร์เย็นไม่มีกลิ่น / ความสะอาด+เก็บของคืนครบ
- + ทดลองขับ (บันทึกระยะทาง) + รูป + บันทึก
- ตีกลับ → ระบุปัญหา + ความสำคัญ (สูง/ปานกลาง/ต่ำ) → สร้าง task `fix` ให้ช่าง

### 3.7 คลังอะไหล่ (Inventory) — Web · **[BIZ]** สูตรสำคัญ
```
คงเหลือใช้ได้ (available) = onHand − reserved
on-order ไม่ใช่ของที่ใช้ได้ · damaged/quarantine ถูกกันออกจากของที่ขายได้
```
- Part: `code, barcode, name, brand, cat, unit, onHand, reserved, onOrder, damaged, rop, pq, cost, price, usage, compat[], suppliers[]`
- **ทุกการเคลื่อนไหวสร้าง ledger entry**: `time, doc, docType, qty, before, after, reason, who`
- docType: ใบเบิกของช่าง (`ISS-`), จองจากใบเสนอราคา, รับของจาก PO (`GRN-`), ปรับสต็อก (`ADJ-`), ตรวจนับ (`CNT-`)
- ปรับสต็อก 4 ประเภท × เหตุผลบังคับ: `damaged`(−) / `loss`(−) / `found`(+) / `return`(+) — ต้องแนบหลักฐาน
- เคสพิเศษที่ออกแบบไว้: บาร์โค้ดซ้ำต่างรหัส (`dup`), รหัสใหม่ยังไม่มีประวัติใช้งาน (`fresh`)

### 3.8 จัดซื้อ + รับของ (Purchasing / GRN) — Web
- PO status: `draft` → `pending` → `approved` → `sent` → `partial` → `complete` · `cancelled`
- **[BIZ]** คิวแนะนำสั่งซื้อเป็น **"คำแนะนำ" เท่านั้น** ผู้ใช้ต้องเลือก ตรวจ และกดสร้างเอง (ไม่ auto-create)
- **[ASSUME]** PO เกิน 10,000 บาท ต้องผู้จัดการอนุมัติ (ดู Open Question #5)
- **[BIZ]** GRN รับบางส่วน → PO **ยังเปิดอยู่** · รับเกินจำนวนต้องเตือน + สิทธิ์อนุมัติ · ของชำรุดที่รับแล้ว **ไม่เข้าสต็อกที่ใช้ได้**
- 4 issue types: จำนวนไม่ตรงใบส่งของ / ราคาต่างจาก PO (ต้องผู้จัดการอนุมัติส่วนต่าง) / ส่งของผิดรายการ (กักกัน) / ของชำรุดจากขนส่ง (ถ่ายรูปแนบ)

### 3.9 POS — Web · 2 ขั้น
**ขั้น 1 · กระทบยอด (Reconciliation)** — **[BIZ]** ต้องตัดสินใจทุกส่วนต่างก่อนเปิดหน้ารับชำระ
เทียบ 3 คอลัมน์: อนุมัติ / ทำจริง / อะไหล่เบิก → 5 สถานะ: `match` ตรงกัน / `over` ทำเกิน / `notdone` ไม่ได้ทำ / ตัดออก / เก็บเพิ่ม

**ขั้น 2 · รับชำระ** — 4 ช่องทาง + แบ่งจ่าย
| ช่องทาง | key | หมายเหตุ |
|---|---|---|
| เงินสด | F2 | ทอนเงินได้ |
| บัตร | F3 | EDC · เคสถูกปฏิเสธ |
| โอนเงิน | F4 | ต้องแนบสลิป |
| PromptPay QR | F5 | QR ระบุยอด |

- **[BIZ]** ปิดการขายไม่ได้ถ้ายอดคงเหลือ ≠ 0 — ยกเว้นบันทึกเป็นลูกหนี้ที่ผู้จัดการอนุมัติ
- **[BIZ]** สถานะไม่ทราบผลต้อง**ไม่**แสดงว่าล้มเหลว: QR หมดเวลา → "กำลังตรวจสอบ" (`checking`) และ**ห้ามให้จ่ายซ้ำ**จนผลตรวจกับธนาคารออก
- ปุ่มยืนยัน**ถูกล็อก**ระหว่างประมวลผล (กันเก็บซ้ำ)
- เอกสาร: ใบเสร็จ `RC-24-xxxx` vs ใบกำกับเต็มรูป `IV-24-xxxx` — **[ASSUME]** ยังไม่รองรับนิติบุคคล/วางบิลประกัน
- **[BIZ]** พิมพ์ซ้ำ/ยกเลิก/คืนเงิน ต้องมีเหตุผล + ผู้ดำเนินการ + ผู้อนุมัติ + เวลา · พิมพ์ซ้ำต้องมีคำว่า "สำเนา/REPRINT" และไม่สร้างเลขใหม่

### 3.10 รายงาน (Reports) — Web · 6 แท็บ
ยอดขายและการรับเงิน / ปฏิบัติการและ SLA / ช่องทางงานตามสถานะ / สต็อกอะไหล่ / จัดซื้อและผู้จำหน่าย / ผลงานช่างและคอมมิชชัน

นิยาม KPI ที่ต้อง implement ให้ตรง:
| KPI | สูตร |
|---|---|
| รอบเวลางาน (Turnaround) | รับรถ → รับรถกลับ **นับเฉพาะเวลาทำการ ไม่รวมช่วงรออะไหล่** |
| SLA เวลานัดส่งมอบ | ส่งมอบไม่เกินเวลานัด**ครั้งล่าสุด** ÷ งานที่ส่งมอบ |
| อัตรา QC ไม่ผ่าน | งานที่ถูกตีกลับ ≥1 ครั้ง ÷ งานที่เข้า QC |
| งานย้อนกลับ (Comeback) | งานซ้ำอาการเดิมภายใน 30 วัน ÷ งานที่ส่งมอบ |
| ค่าซ่อมเฉลี่ยต่อคัน | ยอดสุทธิที่เก็บได้จริง ÷ ใบสั่งซ่อมที่ปิดแล้ว (ไม่รวม VAT) |
| Fill rate ผู้จำหน่าย | จำนวนที่รับครั้งแรก ÷ จำนวนที่สั่ง |
| ส่วนต่างราคา | ต้นทุนจ่ายจริง − ต้นทุนอ้างอิงล่าสุด |
| ค่าคอมมิชชันช่าง | **[ASSUME]** ค่าแรงเก็บได้ × อัตราตามระดับ (8/10/12%) − QC ตีกลับหัก 50% ของค่าแรงงานนั้น |

- **[UI]** ทุกกราฟต้องมี**ตารางเทียบเท่า** + ตัวเลขกำกับทุกแท่ง · ห้ามแกนคู่ / ห้ามกราฟ 3 มิติ
- ข้อมูลตัวเงินถูกกรองตามบทบาท (หัวหน้าช่างเห็นเฉพาะปริมาณงาน ไม่เห็นเงิน)

## 5. Business Rules Catalog

### **[BIZ]** กฎที่ตกลงแล้ว (ต้อง enforce ที่ API ไม่ใช่แค่ UI)
1. เฉพาะรายการที่ลูกค้าอนุมัติจึงเข้าสู่การซ่อมและการเรียกเก็บเงิน · รายการที่ไม่อนุมัติถูกล็อกออกจาก POS
2. ใบเสนอราคาฉบับแก้ไขต้องมีเลขเวอร์ชันใหม่ + เก็บฉบับเดิมเป็น `superseded` · **การอนุมัติและลายเซ็นเดิมใช้กับเวอร์ชันใหม่ไม่ได้**
3. `available = onHand − reserved` · on-order ไม่ใช่ของใช้ได้ · ทุกการรับของสร้าง ledger entry
4. รับของบางส่วน → PO ยังเปิด · รับเกินต้องเตือน+อนุมัติ · ของชำรุดไม่เข้าสต็อกใช้ได้
5. ปิดการขายไม่ได้ถ้ายอดคงเหลือ ≠ 0 (ยกเว้นลูกหนี้ที่อนุมัติ) · ล็อกปุ่มยืนยันระหว่างประมวลผล
6. สถานะการชำระที่ไม่ทราบผลต้องไม่แสดงว่าล้มเหลว · ห้ามจ่ายซ้ำ
7. การกระทำที่ทำลายข้อมูลต้องมีเหตุผล + ผู้ดำเนินการ (ยกเลิกงาน/ยกเลิก PO/คืนเงิน/พิมพ์ซ้ำ/ปรับสต็อก)
8. งานที่พบเพิ่มระหว่างซ่อมยังไม่ถือว่าอนุมัติ · ล็อกเฉพาะรายการนั้น

### **[UI]** กฎหน้าจอ
9. สถานะทุกอย่างสื่อด้วย **สี + ไอคอน + ข้อความ** (ห้ามใช้สีเดียวสื่อความหมาย) · เกินกำหนดใช้แถบซ้าย 5px + ระบุเวลาที่เกิน
10. ฟอร์มยาวบนมือถือใช้ sticky bottom bar + บันทึกร่างทุกขั้น · ออกต้องยืนยัน (เก็บ/ทิ้งร่าง)
11. ข้อมูลที่สร้างตอนออฟไลน์ใช้รหัส `TMP-` + ป้าย "รอซิงก์" · เมื่อซิงก์สำเร็จแสดงการแทนที่ TMP → เลขจริง
12. ทุก state (loading/empty/error/forbidden/stale) ต้องมี **สาเหตุ + ปุ่มถัดไป + รหัสอ้างอิง**

### **[ASSUME]** ค่าที่ตั้งไว้เพื่อสาธิต — **ต้องยืนยันก่อนเขียนโค้ด**
- ส่วนลด > 10% ต้องอนุมัติ
- กำไรขั้นต้น < 15% เตือน
- PO > 10,000 บาท ต้องผู้จัดการ
- SLA เป้า 90%
- คอมมิชชัน 8/10/12% ตามระดับช่าง
